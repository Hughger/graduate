# FLOOD CNN加速器Demo部署执行计划

> **状态说明（2026-08-08）**：这是原 FLOOD CNN Demo 的六周协作计划，现作为历史资料与任务拆分参考保留。当前毕设主线及已确认的技术决策见[正式设计规格](../docs/superpowers/specs/2026-08-08-sd15-resnetblock-accelerator-design.md)，面向 6 个月以上周期的新排期见[SD1.5 ResNetBlock AXKU15 实施计划](../docs/superpowers/plans/2026-08-08-sd15-resnetblock-accelerator-implementation.md)；本文不应被误认为新项目排期。

## 一、项目概况

| 项目要素 | 内容 |
|---------|------|
| 当前状态 | mac_test_tb2完成单层卷积验证，具备多层CNN框架(cnn_multilayer.c) |
| 目标 | 6人协作完成Demo部署，验证加速器通用性 |
| 硬件平台 | AKU15 FPGA + Vivado + Hybrid-SDK |
| 工具链 | RISC-V GCC (riscv64-unknown-elf-gcc) |

## 二、协作模式

### 2.1 总体安排

6人按周轮换任务方向，每周聚焦同一类任务。

| 周次 | 任务主题 |
|------|----------|
| Week 1 | 环境熟悉 + 单层验证复现 |
| Week 2 | LeNet部署 |
| Week 3 | 工具链开发 |
| Week 4 | CIFAR-10部署 |
| Week 5 | 测试验证 |
| Week 6 | FPGA上板 + 优化 |

### 2.2 组内分工

每周6人内部按以下角色分工：

| 角色 | 人数 | 职责 |
|------|------|------|
| 核心开发 | 2人 | 代码编写 |
| 验证测试 | 2人 | 测试用例、结果验证 |
| 文档工具 | 2人 | 文档编写、工具脚本、环境支持 |

## 三、周计划

### Week 1：代码重构 — 模块化拆分

**目标**：将mac_test_tb2拆分为6个独立模块

**任务分配**：

| 人员 | 模块 | 文件 | 内容 |
|------|------|------|------|
| 学生1 | 底层平台 | mac_platform.h/c | 地址宏、寄存器读写、中断、延时 |
| 学生2 | DMA驱动 | mac_dma.h/c | SRAM控制、DMA传输 |
| 学生3 | 配置模块 | mac_config.h/c | Tile/NoC/FSM/全局配置 |
| 学生4 | 数据加载 | mac_data.h/c | 权重/特征图写入 |
| 学生5 | 计算执行 | mac_compute.h/c | 推理执行、输出读取 |
| 学生6 | 测试主程序 | mac_test_single.c + Makefile | main()集成、编译验证 |

**检查点**：
- [ ] 6个模块文件全部提交
- [ ] make all编译通过
- [ ] 仿真结果与原版一致

---

### Week 2：LeNet-5部署

**目标**：在加速器上运行LeNet-5，识别MNIST

**前置准备**（Week 1周末完成）：
- LeNet PyTorch模型和预训练权重
- MNIST测试图片

**任务分解**：

**核心开发组（2人）**
- 编写LeNet网络配置代码（基于cnn_multilayer.c）
- 实现多层推理流程（Conv→Pool→Conv→Pool→FC）
- 输出：lenet_demo.c + lenet_weights.h

**验证测试组（2人）**
- Python实现LeNet软件推理，作为golden reference
- 对比软硬件结果，分析误差
- 输出：lenet_golden.py + 误差分析报告

**文档工具组（2人）**
- 权重量化脚本（PyTorch→C数组）
- 图像预处理脚本（PNG→C数组）
- 输出：quantize_lenet.py + preprocess_mnist.py

**检查点**：
- [ ] LeNet-5仿真运行成功
- [ ] 正确识别至少5张MNIST图片
- [ ] 软硬件误差<5%

---

### Week 3：工具链完善

**目标**：建立PyTorch到加速器的完整工具链

**任务分解**：

**核心开发组（2人）**
- 封装通用CNN推理API（不依赖具体网络）
- 实现层配置自动生成函数
- 输出：cnn_api.c/h

**验证测试组（2人）**
- 测试工具链各环节正确性
- 建立回归测试基线
- 输出：toolchain_test.py + 测试报告

**文档工具组（2人）**
- 权重量化工具（支持任意网络）
- ONNX模型解析器（基础版）
- 输出：quantize_model.py + onnx_parser.py

**检查点**：
- [ ] 工具链能处理任意简单CNN
- [ ] 量化误差<2%
- [ ] 工具使用文档完整

---

### Week 4：CIFAR-10部署

**目标**：部署CIFAR-10分类器，验证工具链可用性

**任务分解**：

**核心开发组（2人）**
- 使用Week 3工具链自动生成CIFAR-10配置
- 调试多层网络在加速器上的运行
- 输出：cifar10_demo.c（工具链自动生成）

**验证测试组（2人）**
- 测试CIFAR-10准确率
- 分析各层耗时，找出瓶颈
- 输出：性能分析报告

**文档工具组（2人）**
- 优化预处理脚本（支持批量处理）
- 编写Demo使用文档
- 输出：batch_preprocess.py + 用户手册

**检查点**：
- [ ] CIFAR-10 Demo运行成功
- [ ] Top-1准确率>60%
- [ ] 工具链能一键生成Demo

---

- 输出：技术文档 + 演示材料

**检查点**：

- [ ] 文档完整，可交付
