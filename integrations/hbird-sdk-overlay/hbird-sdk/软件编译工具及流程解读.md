# 软件编译工具及流程解读（application/custom/axi_test）

本文针对 application/custom/axi_test 目录的软件部分，结合 NUCLEI_TOOL_ROOT 与 setup.bat，系统梳理从 C 程序到 SoC 上运行的完整链路：编译、链接、镜像生成与加载，以及 HAL/驱动与编程模型。结论与证据均给出明确文件与行号引用，便于复核。

---

## 1. 开发与编程模型

- 头文件与寄存器定义
  - SoC 外设头文件聚合：`SoC/hbirdv2/Common/Include/hbird_sdk_soc.h`（汇总包含 UART/GPIO/I2C/SPI/PWM 等）用于标准外设访问。
  - SoC 寄存器映射与基地址：`SoC/hbirdv2/Common/Include/hbirdv2.h`，定义了 PLIC/CLINT 基址与各外设的寄存器结构体与基地址，例如 GPIO/UART/I2C/PWM 等。参考：
    - PLIC/CLINT 基址：`SoC/hbirdv2/Common/Include/hbirdv2.h:155`、`:165`
    - 外设基地址：`SoC/hbirdv2/Common/Include/hbirdv2.h:515` 起（如 `GPIOA_BASE`/`UART0_BASE` 等）
  - 本项目的“自定义硬件”（MAC/DMA/NoC/SRAM 控制等）地址并不在上述标准头文件中，而是直接在应用源码中用宏定义：
    - 基地址与控制块：`application/custom/axi_test/main.c:3`–`:11`（S1/S2/S3/S4/S5/S6/S7/CTRL 与 `DMA_APB_BASE`）
    - DMA寄存器偏移：`application/custom/axi_test/main.c:50`–`:56`（`DMA_CTRL`/`DMA_STATUS`/`DESC0_*` 等）

- 是否存在 HAL/驱动库
  - 存在。SDK 自带标准外设的 HAL/驱动，位置在 `SoC/hbirdv2/Common/Source/Drivers/`（如 `hbirdv2_uart.c`、`hbirdv2_gpio.c`、`hbirdv2_spi.c` 等），其 API 头文件在 `SoC/hbirdv2/Common/Include/`。
    - 例如 UART 初始化与收发：`SoC/hbirdv2/Common/Source/Drivers/hbirdv2_uart.c:4` 起的 `uart_init`/`uart_write`/`uart_read`。
    - GPIO API 原型：`SoC/hbirdv2/Common/Include/hbirdv2_gpio.h:16` 起（`gpio_enable_output`/`gpio_write` 等）。
  - 对于本项目的“自定义模块”（DMA/MAC/NoC），未见独立 HAL，应用层直接通过 `volatile` 寄存器访问读写。

- 应用中与题述功能直接对应的核心函数
  - 配置并启动 DMA 传输：`dma_transfer`（一维搬运），`application/custom/axi_test/main.c:2404`。内部按顺序配置 `DESC0_MODE/LENGTH/SRC_ADDR/DST_ADDR`，然后写 `DMA_CTRL` 启动，并轮询 `DMA_STATUS` 等待完成（`wait_dma_complete`：`:2344`）。
    - 说明：当前实现为 1D 传输（长度为字节数），未见二维（2D）寻址步长配置寄存器。
  - 向 MAC Unit 本地 RAM 写入：
    - 直接写数据到 S1 后，用 DMA 搬运到权重 RAM（地址映射在 S4）：`drive_weights_from_files`，`application/custom/axi_test/main.c:2452`，最终调用 `dma_transfer(S1_BASE_ADDR, S4_BASE_ADDR, length*32)`。
    - 将特征图分 tile/行段搬运到 MAC 输入本地 RAM（S3）：`drive_feature_from_files`，`application/custom/axi_test/main.c:2488`，循环中调用 `dma_transfer(S1_BASE_ADDR+..., S3_BASE_ADDR + ((tileId & 0xFF) << 5), 32)`。
  - 配置 NoC 拓扑：`config_tiles_and_noc`，`application/custom/axi_test/main.c:2296`。按 tileId/nocId 计算配置位，写入 S2（`TILE_CONF_START`/`NOC_CONF_START`）对应的地址窗口。
  - 其他关键：SRAM 归属切换 `set_sram_control`（`application/custom/axi_test/main.c:2332`）用于在“外部写入”和“MAC 接管”之间切换；FSM 与全局控制在 `run_process`（`:2515`）内完成。

## 2. 编译工具链与构建系统

- 工具链前缀
  - 本工程在应用目录下使用手写 Makefile，显式指定 `CROSS_COMPILE = riscv64-unknown-elf-`，参考 `application/custom/axi_test/Makefile:33`。
  - setup 脚本通过 NUCLEI_TOOL_ROOT 提供工具链路径：`setup.bat` 将 `%NUCLEI_TOOL_ROOT%\gcc\bin`、`openocd\bin`、`build-tools\bin` 加入 PATH（`setup.bat:12`）。常见 Nuclei 工具前缀为 `riscv-nuclei-elf-`；本项目 Makefile 采用的是通用的 `riscv64-unknown-elf-` 前缀。

- 构建系统
  - 本项目使用应用目录下的“手写 Makefile”（非 SDK 顶层通用构建），文件：`application/custom/axi_test/Makefile`。
  - SDK 顶层仍提供了通用构建入口（根目录 `Makefile`），但与本自定义应用的 Makefile 无强依赖。

- 关键编译选项（Compiler Flags）
  - ISA/ABI/模型：`-march=rv32imac -mabi=ilp32 -mcmodel=medany`（`application/custom/axi_test/Makefile:16`、`:30`）。
  - 优化与体积：`-Os -ffunction-sections -fdata-sections -Wl,--gc-sections`（`:17`–`:19`、`:28`）。
  - 裸机/无 C 运行库：`-nostdlib -nostartfiles -fno-builtin`（`:18`、`:29`）。
  - 其他：`-g`（符号）、`-std=c99 -Wall -Wextra`，并在链接阶段禁用链接器 relax：`-Wl,--no-relax`（`:22`、`:29`）。

## 3. 链接与内存布局（Linker Script）

- 自定义链接脚本
  - 文件：`application/custom/axi_test/link.ld`。
  - ITCM（指令 TCM）与 DTCM（数据 TCM）布局：
    - ITCM：`itcm (rxai) : ORIGIN = 0x80000000, LENGTH = 256K`（`link.ld:12`）。
    - DTCM：`dtcm (wxa)  : ORIGIN = 0x90000000, LENGTH = 256K`（`link.ld:15`）。
    - 程序入口：`ENTRY(_start)`（`link.ld:7`）。
  - 段落放置：
    - 代码段 `.text`/只读数据 `.rodata` → `> itcm`（`link.ld:24`–`:33`）。
    - 已初始化数据 `.data` → 运行时在 DTCM，加载地址 LMA 在 ITCM：`> dtcm AT > itcm`（`link.ld:36`–`:45`、`:69`）。
    - BSS `.bss` → `> dtcm`（`link.ld:48`–`:58`）。
    - 栈 `.stack` → `> dtcm`，4KB（`link.ld:61`–`:66`），并导出 `__stack_top`（`link.ld:19`）。
    - 全局指针：`PROVIDE(__global_pointer$ = __data_start + 0x800);`（`link.ld:72`）。
    - 容量断言：确保代码不溢出 ITCM、数据不溢出 DTCM（`link.ld:75`–`:76`）。
  - 对比 SDK 参考脚本：官方 ILM 模式脚本默认 64KB ITCM/DTCM（`SoC/hbirdv2/Board/mcu200t/Source/GCC/gcc_hbirdv2_ilm.ld:20`），而本项目脚本将其扩展到 256KB，以适配较大的 `.text`/数据。

- 启动流程（与链接的协同）
  - 启动入口与运行时初始化：`application/custom/axi_test/startup.S`
    - 复位入口 `_start`：`startup.S:10`。
    - 关中断与设栈：`csrw mstatus, zero`（`:12`），`la sp, __stack_top`（`:16`）。
    - BSS 清零：`la t0, __bss_start` / `la t1, __bss_end` 并循环清零（`:19` 起）。
    - .data 复制：从 `__data_lma`（ITCM）拷贝到 `__data_start`..`__data_end`（DTCM）（`:29` 起），与 `link.ld` 的 `> dtcm AT > itcm` 对应。
    - 设置 `gp`（全局指针）后跳转 `main`：`jal ra, main`（`:50`）。

- 段地址小结
  - `.text`/`.rodata` 链接到 ITCM：0x8000_0000 起。
  - `.data`/`.bss`/`.stack` 链接到 DTCM：0x9000_0000 起（栈从 DTCM 顶部向下生长）。

## 4. 镜像生成与加载机制

- 生成物与用途（均由应用 Makefile 产生）
  - ELF：`axi_test.elf`
  - 纯二进制：`axi_test.bin`
  - Verilog Memory：`axi_test.verilog`（`objcopy -O verilog`，`application/custom/axi_test/Makefile:73`）
  - “纯 hex 文本”：`axi_test.hex`（逐 64bit 小端行式文本，便于 `$readmemh` 读入，`application/custom/axi_test/Makefile:66`–`:68`）
  - 链接映像与反汇编：`axi_test.map`、`axi_test.dump`

- 具体命令链
  - 链接：`$(CC) $(OBJS) $(LDFLAGS) -o axi_test.elf`（`application/custom/axi_test/Makefile:59`）。
  - 转 bin：`objcopy -j .text -j .data -O binary --set-start 0x80000000 axi_test.elf axi_test.bin`（`:66`）。
  - bin→hex：使用 Python 将 `axi_test.bin` 按 8 字节一组转为 16 位十六进制文本行（小端），便于 `$readmemh` 直接加载（`:67`）。
  - 另一路：`objcopy -O verilog axi_test.elf axi_test.verilog`（`:73`）。

- 加载到的物理存储器
  - 从链接脚本与启动流程推断，`.text` 起始地址为 ITCM 0x8000_0000，故仿真/FPGA 运行时应将 `axi_test.hex` 或 `axi_test.verilog` 初始化到 ITCM 对应的 BRAM/指令存储中，使 CPU 复位后从 0x8000_0000 取指执行。
  - 数据段 `.data` 在 DTCM（0x9000_0000）运行，启动代码负责从 ITCM 的 LMA 将其复制到 DTCM 的 VMA。

- 说明
  - `axi_test.hex` 是“裸十六进制行格式”（每行 64bit），并非 Intel HEX 记录格式；对应 `$readmemh` 的典型用法：`$readmemh("axi_test.hex", mem);`。
  - `axi_test.verilog` 为 GNU objcopy 生成的 Verilog memory 格式文件，也可直接 `$readmemh` 读入。

## 5. 从 C 程序到硬件执行：端到端流程

1) 预置环境与工具链
- 运行 `setup.bat` 设置环境变量 `NUCLEI_TOOL_ROOT` 并扩展 PATH（`setup.bat:1`、`:12`），从而找到交叉编译器、OpenOCD 等工具。

2) 编译
- `gcc`（`riscv64-unknown-elf-gcc`）用 `-march=rv32imac -mabi=ilp32 -mcmodel=medany -Os` 等选项分别编译 `main.c` 与 `startup.S` 为目标文件（`application/custom/axi_test/Makefile:49`、`:55`）。

3) 链接
- 使用自定义 `link.ld`，将 `.text` 放入 ITCM，`.data/.bss/.stack` 放入 DTCM，生成 `axi_test.elf`（`:59`）。

4) 启动与运行时初始化
- 复位后从 0x8000_0000 进入 `_start`（`startup.S:10`），清 BSS、拷贝 `.data` 到 DTCM、设 `sp/gp`，跳转 `main`（`startup.S:12`、`:16`、`:29`、`:50`）。

5) 驱动自定义硬件
- 应用通过 `write_reg`/`read_reg`（`application/custom/axi_test/main.c:2276`、`:2280`）直接访问映射寄存器：
  - 配置 Tile/NoC（`:2296`）、切换 SRAM 归属（`:2332`）。
  - 通过 `dma_transfer`（`:2404`）搬运权重/特征（`:2452`、`:2488`）。
  - 触发 FSM/全局控制并运行一次推理（`:2515`）。

6) 用于仿真/FPGA 的镜像
- 依据需求选择 `axi_test.hex` 或 `axi_test.verilog` 初始化 ITCM 存储模型，使处理器能够从 0x8000_0000 取指启动并运行。

## 6. 针对问题的简明回答

- 开发与编程模型
  - 头文件：
    - `SoC/hbirdv2/Common/Include/hbirdv2.h`：定义 SoC 外设寄存器结构与基地址（如 `GPIOA_BASE` 等，见 `:515` 起）。
    - `SoC/hbirdv2/Common/Include/hbird_sdk_soc.h`：聚合 SoC 相关 HAL 头文件，统一对外提供接口。
    - 自定义模块（DMA/MAC/NoC）地址与位域：集中定义在应用源码 `application/custom/axi_test/main.c:3`–`:11`、`:50`–`:56`。
  - HAL/驱动库：存在（UART/GPIO/I2C/SPI/PWM 等），示例函数：
    - `uart_init`/`uart_write`（`SoC/hbirdv2/Common/Source/Drivers/hbirdv2_uart.c:4` 起）。
    - GPIO 系列（`hbirdv2_gpio.h:16` 起）。
    - 自定义 DMA/MAC/NoC 未提供独立 HAL，应用通过封装的寄存器写函数实现：
      - DMA 传输：`dma_transfer`（`application/custom/axi_test/main.c:2404`）。
      - MAC 本地 RAM 写入：`drive_weights_from_files`（权重 S1→S4，`:2452`）、`drive_feature_from_files`（特征 S1→S3，`:2488`）。
      - NoC 拓扑配置：`config_tiles_and_noc`（`:2296`）。

- 编译工具链与构建
  - 工具链前缀：`riscv64-unknown-elf-`（`application/custom/axi_test/Makefile:33`）。
  - 构建系统：应用目录内手写 Makefile（非 CMake/非 SDK 通用规则）。
  - 关键编译选项：`-march=rv32imac -mabi=ilp32 -mcmodel=medany -Os`，并使用 `-nostdlib -nostartfiles -fno-builtin`、`-ffunction-sections/-fdata-sections` 与链接时 `--gc-sections --no-relax`（`Makefile:16`–`:22`、`:28`–`:30`）。

- 链接与内存布局
  - 链接脚本：`application/custom/axi_test/link.ld`。
  - 段布局：`.text/.rodata → ITCM@0x80000000`；`.data/.bss/.stack → DTCM@0x90000000`；`.data` 的 LMA 在 ITCM（`link.ld:36`–`:45`、`:69`）。
  - 栈与堆：脚本中显式分配 4KB 栈（`link.ld:61`–`:66`），堆未单独定义（可由 `_end` 向上增长的方式在需要时扩展）。

- 镜像生成与加载
  - 从 ELF 生成 Verilog/hex 的命令：`objcopy -O verilog` 与“bin→行式 64bit 十六进制”转换（`application/custom/axi_test/Makefile:66`–`:68`、`:73`）。
  - 内存初始化文件格式：
    - `axi_test.hex`：每行 64bit 小端十六进制文本，适配 `$readmemh`。
    - `axi_test.verilog`：GNU objcopy 的 Verilog memory 文本格式。
  - 加载位置：ITCM（通常由仿真 testbench/FPGA BRAM 在复位前用 `$readmemh` 或厂商工具初始化），CPU 自 0x80000000 启动。
