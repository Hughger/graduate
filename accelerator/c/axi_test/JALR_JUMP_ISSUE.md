# JALR跳转问题分析

## 当前状态

### ✅ 已解决的问题
1. **文件格式问题**：已修复，ITCM数据成功加载
2. **MROM执行**：MROM[0]和MROM[1]都正确执行
3. **寄存器值**：t0寄存器值正确（0x80000000）

### ❌ 仍存在的问题
**PC卡在0x00001004，JALR指令执行后跳转未发生**

## 问题详细分析

### MROM代码
- **MROM[0]** (0x00001000): `auipc t0, 0x7ffff` (0x7ffff297)
  - 执行结果：`t0 = 0x00001000 + 0x7ffff000 = 0x80000000` ✅
- **MROM[1]** (0x00001004): `jr t0` (0x00028067 = `jalr x0, 0(t0)`)
  - t0值：0x80000000 ✅
  - 跳转目标：0x80000000 ✅
  - **但跳转未发生** ❌

### JALR指令执行流程（根据代码分析）

1. **IFU阶段（指令获取）**：
   - JALR指令被识别
   - 如果rs1 != x0或x1（这里是x5），需要等待EXU阶段解析
   - BPU设置`bpu_wait`信号，等待寄存器值

2. **EXU阶段（指令执行）**：
   - 读取t0寄存器值
   - 计算跳转目标地址 = rs1 + imm = t0 + 0 = 0x80000000
   - 将最低位清零（地址对齐）

3. **流水线刷新**：
   - JALR指令在EXU阶段执行后，需要检查预测是否正确
   - 如果预测正确，不需要刷新流水线
   - 如果预测错误，需要刷新流水线

### 可能的原因

#### 1. JALR指令预测问题
- JALR指令在IFU阶段被预测为跳转，但目标地址可能不正确
- 在EXU阶段执行后，发现预测正确，但跳转没有发生

#### 2. 流水线刷新问题
- JALR指令执行后，流水线刷新没有正确执行
- 跳转目标地址计算正确，但PC没有更新

#### 3. 地址映射问题
- 跳转目标地址0x80000000可能不在正确的地址映射范围内
- ITCM地址映射可能有问题

#### 4. 指令提交问题
- JALR指令可能没有正确提交
- 指令执行完成，但PC没有更新
