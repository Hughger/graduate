# AXKU15 DDR4 MIG compatibility record

## Evidence collected with Vivado 2024.2

The checked-in AXKU15 user manual describes five `MT40A512M16LY-062E`
components: an 80-bit DDR4 data bus, ten DM/DQS byte lanes, and a nominal
5 GB memory population. Vivado 2024.2's `xilinx.com:ip:ddr4:2.2` was queried
on the actual target part `xcku15p-ffve1517-2-i`.

| Item | Board documentation | Vivado DDR4 MIG 2.2 |
|---|---:|---:|
| Physical DQ width | 80 | 8 to 72 only |
| Exact memory part | MT40A512M16LY-062E | not in built-in part list |
| AXI address width | accelerator contract: 64 | 25 to 36 only |
| Address/command pins | A0--A13 plus WE_n/A14, CAS_n/A15, RAS_n/A16 | 17-bit `c0_ddr4_adr[16:0]` |

The command/address mapping is now explicit in the candidate XDC: the board's
`WE_B`, `CAS_B`, and `RAS_B` pins become `c0_ddr4_adr[14]`, `[15]`, and `[16]`.
This is the DDR4 multiplexing defined for the fitted Micron x16 family, not a
missing-wire workaround.

The failed 80-bit configuration is therefore intentional evidence, not an
implementation defect. A direct 80-bit/XCI implementation must not be checked
in or programmed onto the board with this version of MIG.

## Validated candidate profile (not yet a board-download target)

Vivado accepts and generates an instance template for this *candidate*:

```text
Memory part:       MT40A512M16LY-075
Physical width:    64 bits (DQ[0:63], byte lanes 0:7)
AXI data width:    512 bits
AXI address width: 32 bits
Reference clock:   200 MHz differential
DDR4 period:       750 ps (DDR4-2666)
```

This is useful for interface development because the generated IP exposes the
real ports (`c0_sys_clk_p/n`, `c0_ddr4_dq[63:0]`, `c0_ddr4_dqs_t/c[7:0]`, and
the 512-bit application interface). The matching constraints are generated by:

```powershell
python scripts/extract_ddr4_pins.py --data-width 64 --format mig --output constrs/axku15_ddr4_mig64_candidate.xdc
vivado -mode batch -source scripts/verify_mig_candidate.tcl
```

It is **not** approved for hardware deployment: it leaves DQ[64:79] / byte
lanes 8:9 outside the controller, and the `-075` speed-bin substitution has
not been qualified against the fitted `-062E` components.

## Required closure before DDR4 hardware use

1. Obtain the board vendor's supported 80-bit controller/XCI, or explicitly
   approve a reduced-capacity, unused-lane architecture after signal-integrity
   review. Do not infer approval from the 64-bit candidate.
2. Create or obtain a MIG timing model for the actual `-062E` speed bin. The
   hardware can be clocked below its 3200 MT/s rating, but a different part
   number must still be qualified rather than assumed interchangeable.
3. Confirm parity/ALERT handling and run calibration plus read/write stress on
   the physical board before attaching the diffusion DMA datapath.

The clock/LED bring-up bitstream remains independently verified and is safe to
use while this DDR4 closure work proceeds.

Reference: Micron's [DDR4 part catalog](https://www.micron.com/products/memory/dram-components/ddr4-sdram/part-catalog) lists the fitted `-062E` family at up to 3200 MT/s and the candidate `-075` at 2666 MT/s.
