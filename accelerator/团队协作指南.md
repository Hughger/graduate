# FLOOD 项目团队协作指南

## 📋 分支说明

### 主要分支
- **`dev`** - 开发主分支，所有人的代码最终合并到这里
- **`main`** - 稳定版本分支（可选，用于发布稳定版本）

### 个人开发分支
每个团队成员都应该创建自己的开发分支，格式：`姓名_dev`
- `asic_flood` - 项目负责人的开发分支
- `张三_dev` - 张三的开发分支
- `李四_dev` - 李四的开发分支
- ... 以此类推

## 👥 团队成员操作指南

### 第一次获取项目

```bash
# 1. 克隆项目
git clone https://gitea.ydxs.xyz:11301/CoW/FLOOD.git
cd FLOOD

# 2. 查看所有分支
git branch -a

# 3. 切换到 dev 分支
git checkout dev

# 4. 创建自己的开发分支（用自己的名字替换）
git checkout -b 你的名字_dev

# 5. 推送自己的分支到远程
git push -u origin 你的名字_dev
```

### 日常开发流程

```bash
# 1. 在自己的分支上开发
git checkout 你的名字_dev

# 2. 修改代码后提交
git add .
git commit -m "描述你的修改"

# 3. 推送到远程自己的分支
git push

# 4. 定期从 dev 分支拉取最新代码（保持同步）
git checkout dev
git pull origin dev
git checkout 你的名字_dev
git merge dev  # 合并 dev 的更新到自己的分支
```

### 提交代码到主分支

**方式一：通过 Pull Request（推荐）**
1. 在 Gitea 网页端创建 Pull Request
2. 从 `你的名字_dev` 合并到 `dev`
3. 等待项目负责人审核和合并

**方式二：直接合并（需要权限）**
```bash
# 1. 切换到 dev 分支
git checkout dev

# 2. 拉取最新代码
git pull origin dev

# 3. 合并自己的分支
git merge 你的名字_dev

# 4. 解决冲突（如果有）

# 5. 推送到远程
git push origin dev
```

## ⚠️ 重要规则

### ✅ 应该做的：
1. **只在自己的分支上开发**
2. **提交前先拉取 dev 的最新代码**
3. **写清楚 commit 信息**
4. **定期推送自己的代码到远程**
5. **合并前先测试代码**

### ❌ 不应该做的：
1. **不要直接在 dev 分支上开发**
2. **不要随意修改别人的分支**
3. **不要强制推送（git push -f）到共享分支**
4. **不要提交编译产物（已配置 .gitignore）**

## 🆘 常见问题

### Q1: 如何解决合并冲突？
```bash
# 1. 尝试合并时出现冲突
git merge dev
# CONFLICT (content): Merge conflict in xxx.scala

# 2. 打开冲突文件，找到类似这样的标记：
# <<<<<<< HEAD
# 你的代码
# =======
# 别人的代码
# >>>>>>> dev

# 3. 手动编辑，选择保留哪部分代码

# 4. 标记为已解决
git add 冲突文件名

# 5. 完成合并
git commit -m "解决合并冲突"
```

### Q2: 如何撤销本地修改？
```bash
# 撤销单个文件的修改
git checkout -- 文件名

# 撤销所有修改
git reset --hard HEAD
```

### Q3: 误提交到了错误的分支怎么办？
```bash
# 1. 撤销最后一次提交（保留修改）
git reset --soft HEAD~1

# 2. 切换到正确的分支
git checkout 正确的分支名

# 3. 重新提交
git add .
git commit -m "提交信息"
```
